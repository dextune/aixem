# AIXEM 0.5.3

> **Document ID:** `AIXEM-RELEASE-053-001`  
> **Status:** Informative  
> **Version:** 1.0

## Release Objective

AIXEM 0.5.3 adds the smallest defensible hierarchy layer required to compose independent circuit files. Leaf semantic and layout authority remains intact; `aixproj/2` adds only sheet registration, organizational hierarchy, and explicit project-net membership.

## Delivered Contracts

- feature-gated `.aixem` interface ports and `@PORT` semantic endpoints;
- immutable `aixlayout/2` with interface-port presentation and local route closure;
- immutable `aixproj/2` with digest-locked independent sheets, hierarchy, and project nets;
- qualified project identity and a provenance-preserving project semantic graph;
- deterministic project routing and Sheet, Overview, and Composite views;
- data-driven Workbench hierarchy, search, inspection, and highlighting;
- bounded `compose-project` and `route-project-nets` task routes.

## Conformance Evidence

The release includes H001-H015 target cases and N001-N015 fail-closed fixtures. The corpus covers base composition, one-pin-plus-interface closure, fan-out, name isolation, hierarchy depth, interface routing, Overview, Composite, unknown references, duplicate ownership, digest locking, legacy compatibility, ten-sheet scale, crossing semantics, local/project equivalence collision, and the complete required negative inventory.

Each complete verification pass checks implementation behavior and documentation relationships. The final pass additionally verifies all legacy corpora, full repository tests, three-run hierarchical determinism, generated documentation reproducibility, current requirement evidence, and release-claim integrity.

## Compatibility Boundary

Valid `aixproj/1`, `aixlayout/1`, and non-hierarchical `.aixem` sources remain valid. `.aixsym` and `.aixlib` are unchanged. Legacy canonical leaf SVG and resolved-scene outputs remain byte-identical.

AIXEM 0.5.3 does not claim reusable hierarchical instances, bus interfaces, implicit global nets, native KiCad/OrCAD hierarchy compatibility, SPICE subcircuits, PCB routing, or canonical flattening.
