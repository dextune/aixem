# AIXEM 0.5.7 Document Information Architecture and Governance

AIXEM 0.5.7 makes repository documentation placement, identity, lifecycle, and discovery explicit and machine-verifiable. It preserves the canonical `docs/` system while governing plans, validation narratives, fixture instructions, evidence reviews, root entrypoints, and generated products as distinct repository document roles.

## Added

- Repository Document Governance Contract 1;
- Documentation Authoring and Lifecycle Guide;
- repository document policy and JSON Schema;
- canonical path migration registry and generated migration index;
- deterministic repository-wide Markdown inventory;
- role-aware orphan and discoverability validation;
- root Markdown whitelist and reserved filename validation;
- controlled canonical `domain` and `kind` vocabularies;
- deterministic checking of retrieval token estimates;
- terminal canonical-footer and release-patch-marker gates;
- canonical old-path HTML redirects;
- agent pre-create, move, deprecate, archive, and delete rules.

## Reorganized

Historical implementation plans now live under `planning/releases/<version>/` and are registered by `planning/index.yaml`. Human-readable validation narratives now live under `validation/releases/<version>/`, while machine-bound evidence and suite identities retain stable paths unless their complete consumer chain is deliberately migrated.

The repository root is limited to conventional entrypoints. `START_HERE.md` remains an approved exception because the cold-start stage compiler uses that exact filename as an isolated evaluation entrypoint.

## Canonical Cleanup

Current canonical documents no longer contain release patch block comments or authored material after the canonical footer. Release-prefixed addendum headings were integrated as current-state sections while explicit legacy anchors preserve route and link compatibility.

Four ambiguous canonical basenames were clarified. Stable document IDs remain unchanged and prior site paths resolve through the path migration index and generated redirect pages.

## Authority and Compatibility

This release changes documentation paths and governance tooling, not circuit semantics. `.aixem`, `.aixlayout.json`, `.aixsym.json`, `.aixlib.json`, `.aixproj.json`, renderer behavior, Viewer behavior, and live-agent execution contracts remain protected by regression tests and retained output hashes.

Plans explain intended work, release notes summarize change, validation reports record observed results, and canonical documents remain the sole technical authority.
