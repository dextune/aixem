AIXEM 0.5.0

Documents the completed documentation architecture, agent reference compiler, static site, traceability, three-pass hardening, and release integrity system.

AIXEM 0.5.0#

Overview#

AIXEM 0.5.0 turns the 0.4 reference package into a canonical documentation, agent retrieval, publication, and conformance platform.

Document ID: AIXEM-RELEASE-050-001
Status: Informative
Version: 1.0

Release scope#

The release establishes docs/ as the single canonical documentation root and compiles the same source into products optimized for people and AI agents.

Key delivered capabilities include:

  • a stable official-site information architecture;
  • structured metadata on every canonical document;
  • immutable document and requirement identities;
  • nine authored task routes with bounded read budgets;
  • document, route, inverted, dependency, artifact, and traceability indexes;
  • a generated 0.4-compatible reference/ tree;
  • an entirely static documentation site with local search;
  • readable schema pages and an embedded schematic example;
  • complete 0.4 inventory and migration disposition records;
  • requirement-level validator, test, and evidence mapping;
  • three recorded refinement passes;
  • deterministic manifest and ZIP verification tooling.

The exact release counts are generated into release/release-metadata.json and the final validation report rather than duplicated as manually maintained prose.

Preserved schematic invariants#

0.5 does not weaken the 0.4 schematic rules. It preserves:

  • 2.5 mm snap grid and 10 mm major grid;
  • horizontal/vertical orthogonal routes;
  • explicit junction semantics;
  • visual crossings that do not create connectivity;
  • source-level no-connect intent;
  • separation of semantics, symbol representation, layout, and presentation;
  • deterministic project locks and render evidence;
  • original, vendor-neutral AIXEM visual assets.

Canonical and generated boundaries#

docs/**/*.md + docs/_meta authored metadata
        |
        +-- docs/_meta/generated/     compiled indexes and graphs
        +-- reference/                compatibility navigation output
        +-- site/                     static publication output
        +-- validation/               observed validation evidence
        +-- release/                  release metadata and manifest

Generated output is not edited as an independent authority. Any change begins in the canonical source or implementation that owns the behavior.

Three refinement passes#

Pass 1 — Canonicalize#

The 0.4 archive is inventoried by path, size, extension, digest, and language scan. Every source entry receives exactly one migration disposition and at least one canonical document identity. Declared-but-missing historical artifacts are audited and resolved in the target release.

Pass 2 — Compile and route#

Canonical documents and authored route YAML are compiled into bounded agent routes, lookup indexes, dependency graphs, artifact ownership, traceability, compatibility cards, and the static publication source. A retrieval corpus verifies known intent resolution and fallback behavior. Repeated builds are compared by digest.

Pass 3 — Publish and conform#

The release renders the example twice, builds and validates the official site, captures desktop and narrow-layout evidence, runs the repository test suite, materializes requirement evidence, verifies manifest coverage, and packages a deterministic ZIP.

The previous reference/ layout remains available as generated compatibility output. Canonical authority now resides in docs/; consumers should migrate to stable document IDs and the generated route index while retaining the compatibility tree only for transition.
