AIXEM 0.5.9 Integrated Authoring, Library, Pin Semantics, and Placement Hardening

Establishes canonical reusable-library authoring, source-or-placeholder part integrity, pin semantics, bounded electrical compatibility, deterministic placement assistance, and task-oriented Agent guidance.

AIXEM 0.5.9 Integrated Authoring, Library, Pin Semantics, and Placement Hardening#

AIXEM 0.5.9 implements the integrated authoring-hardening program on top of the verified 0.5.8.1 baseline. It makes reusable part creation, component semantics, pin meaning, placement decisions, validation claims, and Agent retrieval more explicit without changing the core file-format schema URIs or expanding the Renderer and Reference Viewer.

Release Purpose#

A fresh Agent can now follow a bounded chain from task intent to canonical authority:

AGENTS.md / REFERENCE.md
    -> docs/authoring/guides/index.md
    -> task-specific guide and route
    -> canonical specification
    -> validator and evidence

New reusable assets use library/<electronics|architecture>/.... Concrete real-world parts require source-bound provenance; unresolved concrete intent remains an explicit placeholder. Symbol reuse remains permitted, while geometry-only multiplication of semantic component IDs is rejected.

Authoring and Library Integrity#

  • Added the canonical singular library/ root and the controlled first-level domains electronics and architecture.
  • Added lower-kebab namespace and compound-file naming rules for new .aixlib.json and .aixsym.json artifacts.
  • Preserved in-place repair of explicitly referenced legacy library paths while blocking new legacy-style roots in ordinary authoring.
  • Added datasheet-backed, generic-template, and placeholder component provenance classes.
  • Added source-or-placeholder enforcement, minimum semantic contracts, semantic-clone detection, and source-bound part-review evidence.
  • Migrated current Agent-visible authoring examples through their generators while retaining explicit legacy compatibility fixtures.

Scalable Library-Part Production Queue#

  • Added an operational planning/library-parts/ workspace that is explicitly isolated from production library/ authority.
  • Added minimal Markdown checkbox items containing only target folder and part name, fixed three-digit category shards, and a 100-item shard ceiling for bounded Agent context.
  • Added deterministic queue validation, next-item selection, category progress, date-created enumeration, and review-pending inspection through tools/library_backlog.py.
  • Added dated generation logs and separate independent review logs so a specific day's successful work can be re-opened and checked without relying on conversation history.
  • Queue completion never promotes semantic claims: each selected item still executes the normal provenance, semantic, symbol, binding, render, and separated-validation workflow.

Grid, Symbol Sizing, and Placement#

  • Preserved the reference rhythm G=2.5 mm, P=5 mm, and M=10 mm.
  • Consolidated outward G quantization, repeated-pin span, standard lead, and readable field-clearance guidance.
  • Closed active-style-profile grid authority against serialized layout declarations.
  • Added deterministic half-away-from-zero snapping and bounded X/Y/XY alignment suggestions.
  • Added evidence-ranked placement guidance, anchor selection, route-channel reservation, deterministic tie-breaking, and minimal-diff modification rules.
  • Placement assistance remains derived and read-only; .aixlayout.json remains authoritative.

Pin Semantics and Bounded Compatibility#

  • Preserved port.type as the electrical behavior axis.
  • Added versioned metadata.pinSemantics facets for signal class, functional tags, polarity, differential pairing, power-domain hints, capabilities, and alternate functions.
  • Added consistency checks for no-connect contradictions, source review, alternate functions, and differential-pair closure.
  • Added a deliberately bounded compatibility precheck with PASS, WARN, ERROR, and NOT_EVALUATED outcomes.

The precheck does not claim voltage compatibility, timing correctness, electrical safety, simulation correctness, or production readiness.

Validation Claim Boundary#

AIXEM 0.5.9 reports distinct outcomes:

STRUCTURAL_PASS
PART_SEMANTIC_PASS | GENERIC_TEMPLATE_PASS | PLACEHOLDER
PIN_SEMANTIC / COMPATIBILITY RESULT
CIRCUIT_INTENT_REVIEW_PASS

A successful render remains a structural result. It is not evidence of datasheet correctness, semantic readiness, or circuit suitability by itself.

Compatibility and Deliberate Non-Goals#

The release does not bump .aixem, .aixlayout.json, .aixsym.json, .aixlib.json, or .aixproj.json schema URIs. Existing safe legacy references remain readable and repairable. Unchanged authoritative inputs retain deterministic Renderer and Viewer behavior.

The release deliberately does not add a datasheet crawler, manufacturer catalog importer, full ERC engine, simulation binding, simulation solver, global auto-layout solver, GUI editor, or universal lower-level part taxonomy.

External-Agent Claim Boundary#

No external AI Tier B execution is performed by the 0.5.9 verification process. These flags remain false:

externalTierBExecuted=false
liveExternalAgentExecuted=false
liveClaimAuthorized=false
