AIXEM 0.5.8 Pre-Live Agent Readiness Hardening

Proves the deterministic platform boundary immediately below a future external AI agent through portable execution, immutable-stage postflight checks, process-tree cleanup, evidence hygiene, fair scoring, successful non-AI subprocess closure, and integrated fault retention.

AIXEM 0.5.8 Pre-Live Agent Readiness Hardening#

AIXEM 0.5.8 closes deterministic platform-side ambiguity before the first real external AI agent is connected. It does not add schematic capability, provider-specific integration, repair hints, context optimization, an editor DSL, or any other speculative AI feature.

Hardened Boundaries#

  • Agent Evaluation 3 results and work roots are safe outside the repository and may contain spaces.
  • Current repository release, corpus identity and revision, historical corpus baseline, and protocol version are retained separately.
  • Tier A keeps a fixed deterministic build clock; any future Tier B path uses actual UTC execution time.
  • task/**, reference/**, and stage-manifest.json are digest-checked after executor termination.
  • POSIX timeouts terminate the complete executor process group with bounded escalation.
  • stdout, stderr, observation results, nested observation details, and official retained evidence are checked for credential leakage.
  • Write-capable observation events are reconciled with Change-Set 1 without replacing mutation authority.
  • Every official L001-L012 hidden invariant carries an agent-visible task, document requirement, or profile basis.

Deterministic Pre-Live Proof#

Four non-AI subprocess fixtures complete the existing closed loop for create-symbol, create-schematic, route-nets, and compose-project. Each produces valid retained PASS evidence while keeping:

agentClass=test-fixture
externalTierBExecuted=false
liveExternalAgentExecuted=false
liveClaimAuthorized=false

Ten integrated fault fixtures retain missing-executable, non-zero exit, timeout after mutation, immutable task tamper, wrong-authority edit, generated-output edit, zero-exit invariant failure, close failure, malformed observation, and observation secret behavior. The gate also audits isolated staged-reference execution, all eight authoring routes, and platform-only timing and size metrics.

Compatibility#

This release does not change .aixem, .aixlayout.json, .aixsym.json, .aixlib.json, .aixproj.json, renderer output, Reference Viewer behavior, or authoring authority. Protected technical artifacts remain regression-locked.

Claim Boundary#

A pre-live PASS means that AIXEM has proven the deterministic harness on successful and failing non-AI subprocess paths. It does not mean that an external AI agent has run or solved a circuit task. Tier B remains explicitly unexecuted until a named external executor is supplied and its full retained attempt set validates.
